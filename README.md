## 현재 사용할 수 있는 화면

| 주소 | 역할 |
| --- | --- |
| `cloud.html` | 진행자 로그인, 행사 생성, QR, 참가자 관리, 회차 시작·취소, 당첨 기록 |

연결 정보가 없는 빌드에서는 실제 로그인·QR 접수가 비활성화됩니다. 로컬 시제품에는 300명 테스트 명단과 별도 방송 화면이 있습니다.

## 구현 내용

- DB에서 정원 300명과 참가자 ID를 관리합니다. 동명이인, `김*300/9` 같은 이름도 각각 한 명으로 처리합니다. 동일 익명 로그인 사용자의 재전송은 기존 참가 번호를 반환합니다.
- 행사별 진행자 권한, 방송 연결 권한, 참가자 권한을 구분합니다. 참가자는 다른 사람의 명단을 조회할 수 없습니다. 브라우저 세션도 역할별로 분리합니다.
- 회차마다 선착순/최후 생존, 원본 맵 4개, 당첨 인원, 당첨자 제외 여부를 선택합니다. 시작 시 명단과 설정을 고정합니다. 실행 중 새로 접수한 사람은 다음 회차부터 포함됩니다.
- 방송 연결 링크는 10분 유효·1회 사용입니다. 행사마다 한 방송 계정이 실행합니다. DB 실행 권한과 동일 브라우저 잠금으로 같은 회차 중복 실행을 막습니다.
- 결과 ID·인원·중복·실행 권한을 검사하고 결과와 제외 상태를 한 DB 트랜잭션으로 저장합니다. 같은 결과 재전송은 허용하고 다른 결과로 덮어쓰기는 거부합니다.
- 방송은 5초마다 연결을 확인하며 실행 권한은 30초 유효합니다. 연결이 오래 끊긴 회차는 결과 확정을 거부합니다. 추첨 도중 새로고침하면 자동 재추첨하지 않으며 진행자가 취소하고 새 회차를 시작합니다.
- 결과 전송 전 탭의 임시 저장소에 같은 결과를 보관합니다. 응답을 받지 못하면 재추첨 대신 저장을 재시도합니다. 탭을 닫으면 이 임시 정보는 없어질 수 있습니다.
- Supabase Realtime은 행사 변경 알림만 보내고 화면은 권한을 검사하는 RPC로 최신 명단·결과를 받습니다. Realtime 장애 시 5초 주기 조회로 보완합니다. 구슬 좌표는 DB에 전송하지 않습니다.
- 진행자 이력과 CSV는 최근 50개 회차 기준입니다. 전체 회차는 DB에 남습니다. CSV는 수식으로 해석될 수 있는 이름을 보호합니다.

## 프로젝트 연결 순서

1. **새 Supabase 개발 프로젝트**를 준비합니다. 기존 운영 DB에 바로 적용하지 마세요. 아래 첫 SQL은 최초 설치용이며 재실행용이 아닙니다.
2. SQL Editor에서 `supabase/migrations/202611130001_church_draw.sql`, 그다음 `202611130002_realtime.sql`을 실행합니다. 두 번째 파일은 Supabase의 `supabase_realtime` publication에 `public.cd_events`만 추가합니다. 이름·명단·방송 코드는 비공개 스키마에 둡니다. [공식 Realtime 설정](https://supabase.com/docs/guides/realtime/postgres-changes)
3. Auth에서 익명 로그인을 켭니다. 진행자용 이메일 계정은 운영자가 만들고, 일반 사용자가 진행자 계정을 만드는 별도 가입 화면은 제공하지 않습니다. `cd_private`는 Data API 노출 스키마에 추가하지 않습니다.
4. `.env.example`을 `.env.local`로 복사하고 프로젝트 URL, **publishable key 또는 anon key**, 공개 사이트 폴더 URL을 입력합니다. `service_role`·`sb_secret_`는 넣지 않습니다. 빌드 전에 비밀키를 검사하여 거부합니다. 공개키의 접근 범위는 DB 권한으로 제한합니다. [공식 API 키 안내](https://supabase.com/docs/guides/getting-started/api-keys)
5. 아래 명령으로 새로 빌드하고 `dist-cloud` 전체를 HTTPS 정적 호스팅에 올립니다. 사이트 URL은 `/`로 끝나야 하며 실제 `join.html`이 있는 폴더를 가리켜야 합니다. `127.0.0.1`은 휴대폰 QR 접수 주소가 아닙니다.
6. 진행자가 로그인 → 행사 생성 → 방송 연결 링크 생성 → 방송 PC에서 링크 열기 → 시험 참가자 등록 → 회차 시작 순서로 점검합니다.

### 행사장 접수 전에 남은 작업

Supabase 공식 문서의 익명 로그인 기본 제한은 **IP당 시간당 30회**입니다. 같은 교회 Wi-Fi에 모인 300명이 기본 설정으로 가입하면 제한에 걸릴 수 있습니다. 실제 프로젝트의 제한·허용량을 확인하고 행사 조건에 맞게 설정한 뒤 같은 네트워크에서 검증해야 합니다. 문서는 CAPTCHA/Turnstile도 권장합니다. 현재 이 개발본에는 CAPTCHA 화면/토큰 전달을 아직 연결하지 않았으므로, 공개 접수 전 프로젝트·도메인에 맞춘 연결과 시험이 필요합니다. [익명 로그인과 제한](https://supabase.com/docs/guides/auth/auth-anonymous)

## 개발 명령

검증 환경: macOS arm64, Node 24.22.1, pnpm 11.25.0. 설치 시 잠금 파일을 유지합니다.

```sh
pnpm install --frozen-lockfile --shamefully-hoist --ignore-scripts
pnpm typecheck:event
pnpm test:event
pnpm test:cloud
EVENT_DIST=dist-cloud pnpm build:cloud
python3 -m http.server 1236 --bind 127.0.0.1 --directory dist-cloud
```

`http://127.0.0.1:1236/cloud.html`을 엽니다. 종료는 실행 창에서 Ctrl+C입니다. 준비된 `preview` 폴더는 설치·빌드 없이 Python 정적 서버만 실행해 볼 수 있습니다. `file://`로 열지 마세요.
